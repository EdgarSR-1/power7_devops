JWT_SECRET: Qué es y Cómo Generarlo

¿Qué es JWT_SECRET?​

JWT = JSON Web Token. Es un método estándar de autenticación en aplicaciones modernas.

Importante: JWT_SECRET no es un secreto del frontend ni un secreto distinto por usuario. Es un secreto del backend para firmar y validar tokens. El frontend solo recibe el JWT ya firmado.

Ejemplo de flujo:​

1. Usuario entra al app:
   App (frontend) → "Login con usuario/password" → Backend

2. Backend valida y crea un TOKEN firmado con JWT_SECRET:
   token = HMAC-SHA256(payload, JWT_SECRET)
   Backend → Token al frontend

3. Frontend guarda el token de acceso en memoria o almacenamiento seguro:
   LocalStorage, SessionStorage o estado en memoria según la app

4. Próximas peticiones:
   Frontend envía: Authorization: Bearer <token>
   Backend verifica: ¿El token es válido? ¿Está firmado con MI JWT_SECRET?
   Si sí → autorizado

5. Si alguien intenta falsificar el token:
   Backend verifica firma → No coincide → RECHAZADO

JWT_SECRET es la clave que SOLO el backend conoce para firmar y verificar tokens.

Si varias personas usan el mismo backend de desarrollo, deben usar el mismo JWT_SECRET para ese entorno. Si hay varias instancias del backend, todas deben compartirlo para que un token emitido por una instancia siga siendo válido en las demás. El frontend nunca necesita conocer ese valor.

Si JWT_SECRET es débil o se filtra → los atacantes pueden falsificar tokens.

¿De dónde sale JWT_SECRET?​

NUNCA lo hardcodees. Debe ser:

  1. Generado una vez por entorno: Mínimo 32 caracteres aleatorios
  2. Guardado en secreto: Solo en .env.local local, o en K8s Secret/OCI Vault en producción
  3. Compartido entre las instancias del backend de ese entorno: desarrollo compartido, producción compartida, pero no con el frontend

Cómo generarlo (sin riesgos):​

Opción A: OpenSSL (Linux/Mac)

openssl rand -base64 32

Salida típica:

7xK9mQ2rT8vW3sL5pJ1hY6bU0cZ4dF9gE2kN5mX8qR1wS7vB3nJ6tY9lI2oP4aU

Ese string es tu JWT_SECRET. Cópialo y guárdalo solo en .env.local.

Opción B: Python

python3 -c "import secrets; print(secrets.token_urlsafe(32))"

Opción C: Node.js

node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

Todas generan strings seguros y aleatorios.

JWT_SECRET + Telegram + IA: Cómo se relacionan​

En tu backend, todo está conectado:

┌─────────────────────────────────────┐
│      Frontend (React)               │
├─────────────────────────────────────┤
│ • App web: Login → JWT token        │
│ • Usa el token para cada request    │
└─────────────────────────────────────┘
          ↕ (JWT token)
┌─────────────────────────────────────┐
│    Backend (Spring Boot)            │
├─────────────────────────────────────┤
│ • Verifica JWT_SECRET en cada req   │
│ • Si válido → usuario autenticado   │
│ • Crea/actualiza tareas en BD       │
└─────────────────────────────────────┘
          ↕
┌─────────────────────────────────────┐
│    Telegram Bot (ej: my_todolist_bot) │
├─────────────────────────────────────┤
│ • Usuario envía /start al bot       │
│ • Bot pide o reutiliza un token JWT │
│ • Bot usa ese token para consultar  │
│   el backend (como si fuera web)    │
│ • Backend lo valida con JWT_SECRET  │
│ • Bot obtiene datos, muestra en TG  │
└─────────────────────────────────────┘
          ↕
┌─────────────────────────────────────┐
│    IA (DeepSeek API)                │
├─────────────────────────────────────┤
│ • Bot envía: "Analiza esta tarea"   │
│ • IA procesa y devuelve respuesta   │
│ • Bot muestra respuesta en Telegram │
└─────────────────────────────────────┘
          ↕
┌─────────────────────────────────────┐
│    Oracle Database                  │
├─────────────────────────────────────┤
│ • Almacena tareas, usuarios, etc.   │
│ • Backend la consulta/modifica      │
└─────────────────────────────────────┘

Todo está asegurado con JWT_SECRET:

  • Web usa tokens JWT emitidos por el backend
  • Bot usa tokens JWT emitidos por el backend
  • El frontend nunca ve el secreto, solo el token
  • Si alguien falsifica un token → Backend lo rechaza

Dónde se configura en Spring Boot​

En application.properties:

jwt.secret=${JWT_SECRET:defaultSecretIfNotSet}
jwt.expiration=86400000

El ${JWT_SECRET} lee desde .env.local:

JWT_SECRET=7xK9mQ2rT8vW3sL5pJ1hY6bU0cZ4dF9gE2kN5mX8qR1wS7vB3nJ6tY9lI2oP4aU

Nunca en código. Siempre en .env.local (gitignore-ado).

Setup correcto: Paso a paso​

1. Genera JWT_SECRET​

openssl rand -base64 32
# Cópialo: 7xK9mQ2rT8vW3sL5pJ1hY6bU0cZ4dF9gE2kN5mX8qR1wS7vB3nJ6tY9lI2oP4aU

2. Corre setup.sh​

./scripts/setup.sh

3. Cuando te pida JWT_SECRET:​

JWT_SECRET: _
# Pega: 7xK9mQ2rT8vW3sL5pJ1hY6bU0cZ4dF9gE2kN5mX8qR1wS7vB3nJ6tY9lI2oP4aU

4. Cuando te pida Telegram:​

TELEGRAM_BOT_TOKEN: _
# Pega: [TU_TOKEN_DE_TELEGRAM]

TELEGRAM_BOT_NAME: _
# Pega: [TU_NOMBRE_DE_BOT]

5. El script genera .env.local:​

# .env.local (NUNCA en Git)
SPRING_PROFILES_ACTIVE=oracle
JWT_SECRET=7xK9mQ2rT8vW3sL5pJ1hY6bU0cZ4dF9gE2kN5mX8qR1wS7vB3nJ6tY9lI2oP4aU
TELEGRAM_BOT_TOKEN=[TU_TOKEN_DE_TELEGRAM]
TELEGRAM_BOT_NAME=[TU_NOMBRE_DE_BOT]
# ... más config

⚠️ NUNCA HAGAS ESTO​

❌ NO:

# Dockerfile
ENV JWT_SECRET=7xK9mQ2rT8vW3sL5pJ1hY6bU0cZ4dF9gE2kN5mX8qR1wS7vB3nJ6tY9lI2oP4aU
ENV TELEGRAM_BOT_TOKEN=[TU_TOKEN_DE_TELEGRAM]

❌ NO:

// Java
public static final String JWT_SECRET = "7xK9mQ2rT8vW3sL5pJ1hY6bU0cZ4dF9gE2kN5mX8qR1wS7vB3nJ6tY9lI2oP4aU";

❌ NO:

# Git commit
git add .env.local  # NUNCA

✅ SIEMPRE HAZ ESTO​

✅ SÍ:

# .env.local (gitignore-ado)
JWT_SECRET=7xK9mQ2rT8vW3sL5pJ1hY6bU0cZ4dF9gE2kN5mX8qR1wS7vB3nJ6tY9lI2oP4aU

✅ SÍ:

# application.properties (en código)
jwt.secret=${JWT_SECRET}  # Lee desde .env.local

✅ SÍ:

# En producción (OCI/K8s)
# Usa K8s Secrets o OCI Vault
kubectl create secret generic jwt-secret \
  --from-literal=JWT_SECRET=7xK9mQ2rT8vW3sL5pJ1hY6bU0cZ4dF9gE2kN5mX8qR1wS7vB3nJ6tY9lI2oP4aU

Resumen​

QuéDóndeCómoNunca
JWT_SECRET.env.local o Vault/SecretGenerado una vez por entornoHardcodeado en código
Token de usoMemoria del frontend o botEmitido por backend al autenticarseReutilizarlo indefinidamente
Para Bot.env.localCopiado del setupVisible en logs
Para IA.env.localCopiado del setupGuardado en repositorio

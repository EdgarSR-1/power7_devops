Inventario: secretos y configuraciones (backend)

Propósito: documentar dónde están las cosas sensibles y cómo empaquetarlas para compartir con otra persona que quiera desplegar localmente o en su propia cuenta OCI.

Resumen rápido​

  • Nunca incluir secretos en imágenes Docker ni en Git.
  • Mantener un bundle local con: un .env.local (variables), una carpeta wallet/ (archivos de Oracle) y plantillas de k8s para crear Secrets.
  • Documentar los nombres exactos que usa la app (p.ej. db-wallet-secret, dbuser, frontendadmin).

Estructura de ejemplo del bundle (que tú guardas localmente y compartes por cliente)​

  • secrets-bundle/
    • .env.local # variables de entorno (no subir a Git)
    • wallet/ # todos los archivos del wallet de Oracle
      • cwallet.sso
      • ewallet.p12
      • sqlnet.ora
      • tnsnames.ora
    • k8s-secrets/
      • dbuser-secret.yaml # template para kubectl apply -f
      • db-wallet-secret.yaml
      • frontendadmin-secret.yaml

Nota: comprimir antes de compartir, p.ej. tar -czf secrets-bundle.tar.gz secrets-bundle/.

Variables y secretos que la app espera (nombres)​

Secretos (CONFIDENCIALES):

  • db_user
  • dbpassword
  • JWT_SECRET
  • TELEGRAM_BOT_TOKEN
  • DEEPSEEK_API_KEY
  • ui_username
  • ui_password

Variables de configuración (NO secretas, pero por entorno):

  • SPRING_PROFILES_ACTIVE
  • DEEPSEEK_API_URL
  • OCI_REGION
  • DOCKER_REGISTRY
  • TODO_PDB_NAME

Kubernetes secrets (nombres que aparecen en los YAML actuales):

  • db-wallet-secret (montado como volumen, contiene el wallet y archivos TNS)
  • dbuser (clave dbpassword usada por valueFrom.secretKeyRef)
  • frontendadmin (clave password usada por valueFrom.secretKeyRef)

Archivos del repo donde se referencia configuración / secretos (revisar antes de compartir)​

  • MtdrSpring/backend/.env.example
  • MtdrSpring/backend/.env.local.example
  • MtdrSpring/backend/Dockerfile.example
  • MtdrSpring/backend/build.sh
  • MtdrSpring/backend/deploy.sh
  • MtdrSpring/backend/SETUP_MAIN.md
  • MtdrSpring/backend/src/main/resources/application.properties
  • MtdrSpring/backend/src/main/resources/todolistapp-springboot.yaml
  • MtdrSpring/backend/wallet.example/README.md
  • MtdrSpring/backend/wallet/ (no está en repo, pero es donde deben ir los archivos reales)
  • MtdrSpring/terraform/*.tf (provider, database, containerengine, core, object_storage, repositories)
  • MtdrSpring/env.sh
  • MtdrSpring/utils/state-functions.sh

Recomendación: revisar cada uno de estos archivos y eliminar cualquier valor sensible hardcodeado antes de subir o compartir.

Plantillas pequeñas (ejemplo) para k8s (NO contienen secretos reales)​

  • dbuser-secret.yaml (template):
apiVersion: v1
kind: Secret
metadata:
  name: dbuser
type: Opaque
stringData:
  dbpassword: REPLACE_WITH_DB_PASSWORD
  • db-wallet-secret.yaml (template):
apiVersion: v1
kind: Secret
metadata:
  name: db-wallet-secret
type: Opaque
# datos binarios base64 o usar `kubectl create secret generic db-wallet-secret --from-file=wallet/`

Cómo preparar y compartir el bundle con otra persona​

  1. Crear secrets-bundle/ con la estructura arriba.
  2. Verificar que .env.local contenga todas las variables listadas.
  3. Comprimir el bundle:
cd /path/to/secrets-bundle
tar -czf secrets-bundle.tar.gz .
  1. Entregar al destinatario por un canal seguro (transferencia cifrada, SFTP, etc.).
  2. Instrucciones para el receptor: descomprimir, set -a; source .env.local; set +a y aplicar los k8s secrets si usa OKE.

Notas finales y pasos pequeños siguientes​

  • Paso corto 1: Validar que .env.local.example lista todas las variables necesarias.
  • Paso corto 2: Crear los 3 templates k8s en docs o utils para que cualquiera los edite y aplique.
  • Paso corto 3: Documentar el proceso de montar wallet en OKE (volume vs secret) en la próxima iteración.

# Secretos y Configuración: Guía Práctica

⚠️ **IMPORTANTE: Este proyecto SIEMPRE conecta a Oracle ATP en OCI.** No hay opción local.

## Resumen Rápido: Obligatorios vs Opcionales

| Dato | ¿OBLIGATORIO? | De dónde | Notas |
|------|---------------|---------|-------|
| **SPRING_DATASOURCE_URL** | ✅ Sí | OCI Console | Connection string ATP |
| **SPRING_DATASOURCE_USERNAME** | ✅ Sí | OCI Console | Típicamente: `ADMIN` |
| **SPRING_DATASOURCE_PASSWORD** | ✅ Sí | OCI Console | Al crear instancia |

## 2. JWT_SECRET: Clave para tokens JWT

### ¿Qué es?
Una cadena larga y aleatoria que Spring Boot usa para **firmar y validar tokens JWT** (autenticación).

**No es un secreto del frontend.** El frontend solo recibe el JWT ya emitido por el backend. El secreto lo comparten las instancias del backend dentro del mismo entorno.

### Dónde conseguirlo
**Opción A: Generador online**

```bash
openssl rand -base64 32
# Salida: ejemplo
# 7xK9mQ2rT8vW3sL5pJ1hY6bU0cZ4dF9gE2kN5mX8qR1wS7vB3nJ6tY9lI2oP4aU
```

**Opción B: Python**

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

**Mínimo requerido:** 32 caracteres alfanuméricos (sin espacios).

**Importante para el equipo:**
- Si ya existe un JWT_SECRET para este backend en desarrollo, usen ese mismo valor en todo el equipo para ese entorno.
- Si no existe, generen uno una sola vez y guárdenlo en un lugar seguro compartido por el equipo, no en el repo.
- Producción debe usar otro JWT_SECRET distinto al de desarrollo.

### Cómo se usa
En `setup.sh`, te pedirá:
```
¿JWT_SECRET? (minimo 32 chars): _
```

Spring Boot lo usa en `application.properties`:
```properties
jwt.secret=${JWT_SECRET:default}
```

Ese valor se usa para emitir y verificar tokens. No se recalcula por usuario ni por petición.

## 3. SPRING_DATASOURCE_URL: Connection String de Oracle

### ¿Qué es?
La dirección y credenciales para conectar a tu Oracle ATP (Autonomous Transaction Processing).

### Formato
```
jdbc:oracle:thin:@<nombre_db>_<tipo>?TNS_ADMIN=/mtdrworkshop/creds
```

Desglose:
- `<nombre_db>` = Nombre de tu ATP en OCI (ej: `reacttodok7toc`)
- `<tipo>` = `tp` (Transaction Processing), `dw` (Data Warehouse), etc.
- `TNS_ADMIN=/mtdrworkshop/creds` = Path a los wallet files dentro del contenedor

**Ejemplo real:**
```
jdbc:oracle:thin:@reacttodok7toc_tp?TNS_ADMIN=/mtdrworkshop/creds
```

### Dónde conseguirlo

En **OCI Console**:

1. Ve a **Database** → **Autonomous Transaction Processing**
2. Haz clic en tu instancia (ej: `reacttodok7toc`)
3. En la sección **Database Connection**, haz clic en **Database Actions** o **Show Connection String**
4. Busca la línea con `jdbc:oracle:thin:@...`
5. Cópiala

**Alternativa rápida:**
- Nombre DB: visible en OCI Console
- Tipo: pregunta a tu DBA o revisa OCI (por defecto `_tp`)
- `TNS_ADMIN=/mtdrworkshop/creds` siempre es así en Docker

### Cómo se usa
En `setup.sh`, te preguntará:
```
¿DB Connection String? (ej: jdbc:oracle:thin:@...): _
```

Spring Boot lo usa:
```properties
spring.datasource.url=${SPRING_DATASOURCE_URL}
```

## 4. SPRING_DATASOURCE_USERNAME: Usuario de BD

### ¿Qué es?
Usuario Oracle que tiene acceso a la BD. Normalmente es **`ADMIN`**.

### Dónde conseguirlo
En **OCI Console**:

1. Ve a **Database** → **Autonomous Transaction Processing** → tu instancia
2. En la sección **Database Details**, busca **Administrator**
3. Usuario: **`ADMIN`** (por defecto)
4. Si quieres otro usuario, crea uno con SQL:
   ```sql
   CREATE USER myuser IDENTIFIED BY MyPassword123;
   GRANT CREATE SESSION, RESOURCE TO myuser;
   ```

### Cómo se usa
En `setup.sh`, te preguntará:
```
¿DB User? (default: ADMIN): _
```

---

## 5. SPRING_DATASOURCE_PASSWORD: Contraseña de BD

### ¿Qué es?
La contraseña del usuario Oracle. La defines cuando creas la instancia ATP.

### Dónde conseguirlo
**En OCI:**
1. Al crear la ATP, OCI te pide una contraseña para ADMIN
2. La estableces en ese momento (no se puede recuperar después)
3. Si la olvidaste, debes resetearla en OCI Console

**Requisitos:**
- Mínimo 12 caracteres
- Al menos 1 mayúscula, 1 minúscula, 1 número, 1 símbolo especial
- Ej: `H1elofrio@123`

### Cómo se usa
En `setup.sh`, te preguntará:
```
¿DB Password? (mínimo 12 chars): _
```

⚠️ **NUNCA** la escribas en código, solo en `.env.local` (gitignore-ado).

## 6. Oracle Wallet: Archivos de credenciales

### ¿Qué es?
Un conjunto de archivos (certificados, claves, configuración) que Oracle usa para **autenticar conexiones seguras (mTLS)** a la BD.

Tu wallet se llama `Wallet_reacttodok7toc` (nombre basado en tu DB).

### Archivos necesarios

Cuando descargas el wallet desde OCI, obtienes algo así:

```
Wallet_reacttodok7toc/
├── cwallet.sso          ✅ NECESARIO (credenciales cifradas)
├── ewallet.p12          ✅ NECESARIO (certificado PKCS#12)
├── ewallet.pem          ✅ NECESARIO (formato PEM)
├── keystore.jks         ✅ NECESARIO (Java keystore)
├── truststore.jks       ✅ NECESARIO (confianza de certificados)
├── ojdbc.properties     ✅ NECESARIO (configuración OJDBC)
├── tnsnames.ora         ✅ NECESARIO (direcciones de conexión)
├── sqlnet.ora           ✅ NECESARIO (configuración SQL Net)
└── README               ℹ️  Informativo
```

**TODOS los archivos son necesarios.** Cópialos completos a `MtdrSpring/backend/wallet/`.

### Dónde conseguirlo

En **OCI Console**:

1. Ve a **Database** → **Autonomous Transaction Processing** → tu instancia
2. Haz clic en **Database Connection**
3. Busca **Download Client Credentials (Wallet)**
4. Haz clic en **Download Wallet**
5. Se descarga un ZIP: `Wallet_<tu_db>.zip`

**Descomprímelo:**
```bash
unzip Wallet_reacttodok7toc.zip -d MtdrSpring/backend/wallet/
# O si ya lo tienes en ~/Downloads:
unzip ~/Downloads/Wallet_reacttodok7toc.zip -d MtdrSpring/backend/wallet/
```

O déjalo descomprimido en `~/Downloads/Wallet_reacttodok7toc/` y el `setup.sh` lo copia automático.

### Cómo se usa

Durante `setup.sh`, te preguntará:
```
¿Ruta del Wallet ZIP? (ej: ~/Downloads/Wallet_reacttodok7toc.zip, o Enter para saltear): _
```

El script descomprime a:
```
MtdrSpring/backend/wallet/
```

Spring Boot lo usa (interno):
```
spring.datasource.url=jdbc:oracle:thin:@reacttodok7toc_tp?TNS_ADMIN=/mtdrworkshop/creds
# En Docker: /mtdrworkshop/creds está mapeado a MtdrSpring/backend/wallet/
```

## 7. TELEGRAM_BOT_TOKEN (OBLIGATORIO)

### ¿Qué es?
Token para autenticar tu bot de Telegram. **OBLIGATORIO** para probar el backend.

### Dónde conseguirlo
1. En Telegram, busca **@BotFather**
2. Envía `/newbot`
3. Sigue las instrucciones:
   - Nombre completo del bot (ej: MyTodoListBot)
   - Nombre de usuario único (ej: my_todolist_bot)
4. **Copia el token** que te da

**Token típico:**
```
123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11
```

### Cómo se usa
En `.env.local`:
```bash
TELEGRAM_BOT_TOKEN=123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11
TELEGRAM_BOT_NAME=my_todolist_bot
```

⚠️ **NO dejar vacío.** Sin esto, las pruebas del bot fallarán.

## Troubleshooting

| Error | Causa | Solución |
|-------|-------|----------|
| `ORA-28000` | Wallet corrupto o mal ubicado | Redownload desde OCI |
| `JWT decode error` | JWT_SECRET muy corto | Genera uno nuevo con openssl |
| `Connection refused` | TNS_ADMIN path incorrecto | En Docker es `/mtdrworkshop/creds` |
| `ORA-01017` | Usuario/password incorrectos | Verifica en OCI Console |

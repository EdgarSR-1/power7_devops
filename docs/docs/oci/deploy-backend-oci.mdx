# Deploy del backend en OCI

Esta página será la bitácora mínima para dejar el despliegue limpio y repetible. La idea es avanzar en pasos pequeños y documentar solo lo que ya quedó validado.

## Objetivo

- Desplegar el backend con IP pública en OCI.
- Evitar secretos o wallets dentro de la imagen Docker.
- Separar configuración local, de build y de despliegue.

## Lo que debe quedar fuera del repo o de la imagen

- Credenciales de base de datos.
- Oracle Wallet completo.
- JWT secret.
- Tokens de Telegram y otras APIs.
- Passwords de UI o cuentas de servicio.

## Orden de trabajo

1. Limpiar la configuración confusa o hardcodeada.
2. Definir cómo se inyectan secrets en OCI.
3. Dejar un flujo de build backend independiente.
4. Documentar el despliegue mínimo que sí funciona.

## Estado actual

- El backend ya tiene scripts de build y deploy.
- La documentación existente mezcla setup local con despliegue.
- Aún falta separar qué es local y qué es OCI.

## Inventario inicial

### 1) Secretos que deben vivir fuera del repo

Este grupo tiene 8 valores sensibles o semi-sensibles que no deben quedar embebidos en la imagen ni en archivos públicos:

- `db_user`
- `dbpassword`
- `JWT_SECRET`
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_BOT_NAME`
- `DEEPSEEK_API_KEY`
- `ui_username`
- `ui_password`

### 2) Variables de runtime que no son secreto, pero sí deben parametrizarse

Estas 5 variables controlan el arranque y el despliegue, y conviene tratarlas como configuración por entorno:

- `SPRING_PROFILES_ACTIVE`
- `DEEPSEEK_API_URL`
- `OCI_REGION`
- `DOCKER_REGISTRY`
- `TODO_PDB_NAME`

### 3) Identificadores y datos OCI que conviene tener a mano

Estos 7 datos no son secretos como tal, pero sí son valores de infraestructura que hay que recopilar para no depender de la shell ni de supuestos:

- `ociTenancyOcid`
- `ociUserOcid`
- `ociCompartmentOcid`
- `ociRegionIdentifier`
- `mtdrDbName`
- `runName`
- `mtdrKey`

### 4) Piezas OCI que ya aparecen en la configuración actual

Hay al menos 8 elementos de infraestructura que conviene contar y documentar en el proceso:

- Autonomous Database (ATP)
- Object Storage namespace
- OKE cluster
- Node pool
- VCN
- Subnet de endpoint
- Subnet de service load balancer
- LoadBalancer de Kubernetes para exponer el backend

### 5) Datos que todavía quiero separar del todo

Quedan por clasificar con más cuidado, porque hoy están mezclados entre scripts, YAML y Terraform:

- El wallet de Oracle como secreto montado en runtime
- Los nombres de los secrets de Kubernetes (`db-wallet-secret`, `dbuser`, `frontendadmin`)
- El namespace de despliegue
- Las credenciales de la base externa donde vive la DB principal
- La clave SSH pública del nodo de OKE si se mantiene en Terraform
